# IAM_web(Next.js) ↔ IAM Flutter 기능 대조

> **최초 결론: 동일하지 않다.**
> 라우트 구조·REST 계약·도메인 규칙(phase·CTA·체크인 창)·에러 매핑·날짜 포맷은 **사실상 1:1**로 옮겨졌다.
> 그러나 **웹에 있는데 앱에 없는 기능이 16건**, **앱에만 있는 기능이 10건**, **같은 기능인데 동작이 다른 지점이 12건** 있었다.
> 이 중 사용자가 "못 하게 되는" 진짜 기능 손실이 **5건**, 구조적 구멍이 **2건**이었다.

- 작성일: 2026-07-31 (대조) · 같은 날 P0 5건 + 구조 2건 반영
- 대조 대상: `IAM_web/src` (Next.js 15 · App Router) ↔ `lib/` (Flutter · GetX + Retrofit)
- **확인 방법: 두 저장소의 소스 전량 대조.** 웹 dev 서버는 기동하지 않았고, 화면 캡처 비교도 하지 않았다.
  따라서 아래 항목은 모두 **코드 근거**가 있으며, 픽셀 단위 시각 차이는 이 문서의 범위 밖이다.

**이번에 내린 결정**
- **갤러리 저장 도입** — `gal ^2.3.1`. Android `WRITE_EXTERNAL_STORAGE`(maxSdkVersion 28) ·
  iOS `NSPhotoLibraryAddUsageDescription` 추가. 포스터와 명함이 같은 유틸(`ImageShareUtils`)을 쓴다.
- **포스터 폰트 선택은 제외** — 번들된 서체가 Pretendard 하나뿐이라 서체 에셋·라이선스 결정이 선행돼야 한다.
  `poster_config.dart` 상단에 그 이유를 남겨 뒀다.
- **프로필 항목 식별은 배열 인덱스**(웹과 동일). 인덱스가 밀렸을 때의 동작만 명시했다 —
  `upsert`는 범위를 벗어나면 덮어쓰지 않고 추가하고, `removeAt`은 아무것도 지우지 않는다
  (`test/profile_item_saver_test.dart`).

**실기 검증(에뮬레이터 Pixel 3a · API 34 · dev 서버)**
찜 취소(`DELETE .../likes/{id}` 204) · 관심사 필터(배지·실시간 카운트·빈 상태) ·
프로필 항목 목록/수정/삭제(PATCH 후 배열 길이 유지 = 교체 확인) · 포스터(추천 프리셋 적용,
배색·레이아웃 전환, 갤러리 저장 파일이 **정확히 1080×1080**) · 명함 저장(`쫑미니님의-명함.png`) ·
커버 필수 에러까지 화면에서 확인했다.

**검증 중에 찾은 별개 버그 — 토스트 뒤의 `Get.back()`이 화면을 닫지 않는다 (수정함)**

GetX `back()`은 스낵바가 떠 있으면 **라우트 대신 스낵바만 닫고 반환한다**:

```dart
// get 4.x · extension_navigation.dart
if (isSnackbarOpen && !closeOverlays) { closeCurrentSnackbar(); return; }
```

그래서 `toast.success(...)` → `Get.back(result: true)` 순서인 화면은 저장이 성공해도 그대로 남아
실패한 것처럼 보이고, 호출부가 기다리던 결과값도 전달되지 않아 목록이 갱신되지 않았다.
**이번 작업 이전부터 있던 버그**로, 프로필 편집·명함 등록/삭제·모임 수정이 모두 해당됐다.
`ToastService.backThen()`(닫고 나서 토스트)으로 통일해 6개 경로를 고쳤다.

**아직 남은 것**: 아래 §3의 P1·P2와 §5의 동작 차이. 이번 범위가 아니었다.

## 3. 웹에 있는데 앱에 없는 것

### P0 — 사용자가 못 하게 되는 기능

**① 프로필 경력·이력·링크 개별 수정/삭제 (`/me/profile`)**
- 웹: 경력·이력(학력/자격증/수상/어학)·외부 링크를 **카드 목록으로 나열**하고, 각 카드의 "수정"으로
  `/me/profile/career/[idx]` 등에 진입해 **수정 + 삭제**한다 (`CareerForm`의 `onDelete`).
- 앱: `me_profile_view.dart:_readOnlySection()`이 **개수만 표시**한다 —
  `경력 N개 · 이력 N개 · 링크 N개` + "＋ 추가" 버튼 3개. 코드 주석에도 "편집은 전용 화면이 필요하고, 그건 아직 스텁이다"라고 적혀 있다.
- **결과: 앱에서는 한 번 등록한 경력/이력/링크를 고치거나 지울 수 없다.** 계속 쌓기만 된다.

**② 찜 취소 (`/me/likes`)**
- 웹: "내가 찜한" 탭의 각 행에 **"찜 취소" 버튼**(`SentLikeRow` → `useUnlike`) + 성공 토스트.
- 앱: `me_likes_view.dart:_row()`가 `IamProfileCard`에 `onTap`만 연결. `MeLikesController`에 unlike 호출 자체가 없다.
- **결과: 찜 관리 화면에서 찜을 못 뗀다.** (해당 모임의 프로필 상세로 들어가면 가능하지만, 화면의 목적이 무의미해진다.)

**③ 참가자 목록 관심사 필터 (07b) (`/event/[slug]/people`)**
- 웹: `SearchBar`의 `onFilter`/`filterCount` → `TagSelect` 바텀시트, 적용 전 "결과 보기 (N명)" 미리 카운트, 드래프트→적용 패턴.
- 앱: `IamSearchBar`에 `onFilter` 미연결. `EventPeopleController.hasFilter`가 **검색어만** 본다.
- **결과: 참가자가 많은 모임에서 관심사로 좁혀 볼 수 없다.**

**④ 홍보포스터 편집 (`/event/[slug]/poster`)**

| 항목 | 웹 (`PosterEditor.tsx`) | 앱 (`event_poster_view.dart`) |
|---|---|---|
| 배색 | 그라데이션 6 + **솔리드 6** = 12종 | 그라데이션 **6종만** |
| 레이아웃 | **4종**(editorial·centered·band·hero) + 썸네일 미리보기 | ❌ 없음 |
| 폰트 | **선택 가능**(FONT_ORDER) | ❌ 없음 |
| 제목 크기 | **작게/보통/크게** | ❌ 없음 |
| 소개 문구 | **Textarea로 직접 편집** + 표시 토글 | 표시 토글만 (원문 고정) |
| 추천 프리셋 | 카테고리 기반 추천 + "↺ 추천으로" 복원 | ❌ 없음 |
| 전체화면 크게 보기 | ✅ | ❌ 없음 |
| 저장(다운로드) | ✅ 저장 + 공유 2버튼 | **공유만** |
| 캡처 해상도 | 오프스크린 1080px 실치수 | 미리보기 3배 (화면 폭 의존) |
| 주최자 가드 | `RequireOrganizer` | ❌ 없음 |

**⑤ 명함 저장·공유 (`CardViewerSheet`)**
- 웹: 명함 뷰어 시트에 **저장 / 공유** 버튼, 앞·뒤 전환 도트, "내 명함"도 탭하면 뷰어가 열린다.
- 앱: `_viewCard()`가 앞/뒤 이미지를 세로로 나열만 한다. **저장·공유 없음.** 내 명함 카드는 탭 불가.

### P1 — 정보/흐름 손실

**⑥ 헤더 알림 드롭다운 (와이어프레임 15)**
- 웹: 벨 클릭 → 최근 6건 드롭다운(모두 읽음 · 전체 보기 · 항목 탭 시 딥링크). 홈 + `AppTopBar`(내 모임·찜·마이) 전부.
- 앱: 벨이 **홈·마이 2곳에만** 있고, 누르면 `/me/notifications` 전체 화면으로 **이동**한다. 내 모임·찜 화면엔 벨 자체가 없다.

**⑦ 명함첩 "보낸 요청" 탭의 거절 이력**
- 웹: `direction=sent`에서 `pending` + **`rejected`** 를 함께 보여주고, 거절건은 "삭제"(localStorage 로컬 숨김)로 정리한다.
- 앱: `MeCardsController.load()`가 `sent`를 `status == pending`으로만 거른다. **거절된 요청이 아예 안 보인다.**

**⑧ 명함첩 탭 서브헤더 카운트** — 웹의 "교환한 명함 N" / "N건 대기 중"이 앱엔 없다.

**⑨ 프로필 상세의 "내 명함 등록하기" 인라인 링크**
- 웹: 명함 미등록 시 캡션에 `/me/cards/edit`로 가는 링크를 함께 준다.
- 앱: 캡션 텍스트만 뜬다. (`EventPeopleDetailController.openCardEdit()`은 정의돼 있으나 **뷰에서 호출되지 않는다**.)
- 덧붙여 웹은 "찜 불가" 캡션과 "명함 미등록" 캡션을 **동시에** 쌓아 보여주지만, 앱의 `_caption()`은 switch 첫 매치 하나만 보여준다.

**⑩ 모임 생성/수정 — 커버 이미지 필수 + 추천 커버**
- 웹: Zod 스키마에서 `cover_image_url` **필수**(미선택 시 "커버 이미지를 선택해 주세요."), 추가로 **추천 커버 5종**(Unsplash)을 눌러 바로 선택 가능.
- 앱: `ChannelFormMixin.validate()`에 커버 검증이 **없다**. 추천 커버도 없다.
- **결과: 앱에서는 커버 없는 모임이 만들어질 수 있다.** (웹 목록/카드가 커버를 전제로 그려지므로 데이터 일관성 문제)

**⑪ 모임 수정 화면의 "취소" 버튼** — 웹 `ChannelForm`의 `onCancel` 보조 버튼. 앱엔 없다.

**⑫ 홈 상태 필터의 자동 추가 로드**
- 웹: 상태 칩(모집중/진행 중/지난 모임)은 클라이언트 필터라 현재 페이지가 통째로 걸러지면 sentinel이 사라져 무한스크롤이 멈춘다 → **결과가 빌 동안 다음 페이지를 계속 당겨오는** effect가 있다.
- 앱: 같은 안전장치가 없다. 상태 필터를 켰을 때 첫 페이지가 전부 걸러지면 **"해당하는 모임이 없어요"가 뜬 채 멈춘다.**

### P2 — 가드·개발 도구

## 4. 앱에만 있는 것

1. **스플래시(`/splash`)** — 세션 부트스트랩 + 참조 데이터 로드 + 최소 노출 600ms, 이후 분기.
2. **FCM 푸시 전체** — 권한 요청(온보딩 완료 시점), 토큰 등록/해제(`/users/me/devices`), 토큰 갱신 추적,
   포그라운드 로컬 알림, 알림 탭 → 딥링크(`push_router.dart`). **웹 `push.ts`는 전부 no-op 스텁이다.**
3. **설정: 이메일 알림 토글** — 낙관적 반영 + 실패 시 롤백. 웹은 `useSettings()`를 호출만 하고 **토글 UI가 없다**(로그아웃·탈퇴·약관만).
4. **설정: 로그인 계정 표시 + 탈퇴 제한 안내 문구.**
5. **당겨서 새로고침** — 홈·내 모임·찜·명함첩·알림·참가자 목록.
6. **모임 수정 안내 배너** — "일시·장소를 바꾸면 참가자에게 변경 알림이 가요."
7. **참가자 관리 탭에 건수 표시** — "승인 12 / 대기 3 / 거절 1".
8. **네트워크 에러 문구** — `TIMEOUT`·`NETWORK` 매핑 추가(웹엔 없음).
9. **카카오 네이티브 SDK 로그인** — 웹의 authorize 리다이렉트 대신 `id_token`을 받아 같은 엔드포인트로 보낸다.
   (키 부재 시 테스트 로그인으로 폴백하던 경로는 인증 우회라 제거했다.)
10. **화면 꺼짐 방지(wakelock_plus)** — 웹의 Screen Wake Lock API 대응. 미지원 브라우저 경고 배너는 앱에선 불필요.

## 5. 같은 기능, 다른 동작

| # | 지점 | 웹 | 앱 | 영향 |
|---|---|---|---|---|
| 1 | 홈 필터 적용 | 클라이언트 필터만(재조회 없음) | `applyFilter()` → **서버 재조회** | 네트워크 왕복 발생, 결과는 유사 |
| 2 | 가나다순 정렬 | `localeCompare(..., "ko")` | `String.compareTo` (코드유닛) | **한글 정렬 순서가 다를 수 있다** |
| 3 | 데이터 로딩 단위 | 화면/탭별 독립 쿼리 + 캐시(TanStack) | 컨트롤러가 `Future.wait`로 일괄 | 앱은 **하나 실패 시 화면 전체가 에러**(내 모임·명함첩·찜). 대시보드만 개별 처리 |
| 4 | 페이지 크기 | 서버 기본값(참가자·likes), 100(교환) | **하드코딩**: 내 모임 50, 참가자 100, 교환 100 | 초과분이 조용히 잘린다(양쪽 다 무한스크롤 없음) |
| 5 | 명함첩 탭 딥링크 | `?tab=received` 지원 | 미지원 — 항상 첫 탭 | 알림에서 "받은 요청"으로 못 간다 |
| 6 | 알림 항목 탭(알림센터) | 명함 교환 알림 → `/me/cards(?tab=received)` | `channel.slug`가 있을 때만 이동 → **명함 교환 알림은 무반응** | 푸시 탭(`push_router`)은 `meCards`로 정상 이동 |
| 7 | 하단 탭 라벨 | "내 모임" | **"모임"** | 표기 불일치 |
| 8 | 모임 수정 완료 후 | 상세로 `replace` | `Get.back(result: true)` | 진입 경로에 따라 도착지가 다르다 |
| 9 | 스켈레톤 최소 노출 | 350ms 보장(`useMinimumLoading`) | 없음 | 빠른 응답에서 깜빡임 가능 |
| 10 | 프로필 편집 PATCH | 하위 폼은 `useProfileFormGate`로 me 로드 전 마운트 차단 | 저장 직전 `GET /users/me` 재조회 후 carry-over | 앱 쪽이 더 안전(같은 사고를 다른 방식으로 막음) |
| 11 | 체크인 호스트 wakelock | 창이 열려 있는 동안 유지 + 탭 복귀 시 재획득 | `load()` 시점에 `isOpen`이면 1회 활성화 | **화면을 켜둔 채 창이 열리면 활성화되지 않는다** |
| 12 | 스캐너 불가 안내 | 인앱 브라우저 감지 + "주소 복사해서 기본 브라우저로" | 권한 안내 + "모임 이름으로 검색" | 웹 전용 사정이라 차이 자체는 타당 |

| 찜 빈 상태 | 모임에서 마음에 드는 사람을 찜해 보세요. | 모임 참가자 목록에서 마음이 가는 사람을 찜해 보세요. |
| 알림 빈 상태 | 모임 소식이 오면 여기에 표시돼요. | 모임 소식이 **생기면** 여기에 표시돼요. |
| 참가자 검색 초기화 | 필터 초기화 | 검색 초기화 |

| 공개 모임 설명 | 탐색 피드에 공개됩니다. / 초대 링크로만 접근 가능합니다. | 끄면 링크·QR을 아는 사람만 들어올 수 있어요 |

또한 **모임 생성 폼의 필드 순서가 다르다.**
- 웹: 커버 → 이름 → 소개 → 장소 → 카테고리 → 관심사 → 일정 → 정원 → 공개
- 앱: 커버 → 이름 → **일정** → 장소 → **정원** → 카테고리 → 관심사 → **소개** → 공개

기타 검증 상한 차이: 웹은 정원 **최대 1000**·소개 **최대 2000자**를 스키마로 막지만 앱은 정원 상한이 없다(소개는 `maxLength`로만).
스킬 개수 상한은 웹이 화면마다 다르고(온보딩 20 / 프로필 편집 10) 앱은 **20으로 통일**돼 있다 — 이건 앱 쪽이 일관적이다.

## 7. 의도적으로 다른 것 (수정 대상 아님)

- **세션 전달 방식**: 웹 HttpOnly 쿠키(`credentials: "include"`) ↔ 앱 Bearer 헤더 + `GetStorage`.
  401 분기 규칙(`UNAUTHORIZED`=즉시 로그아웃 / 그 외=refresh 1회 후 재시도)과 single-flight refresh는 동일하다.
- **상태 관리**: TanStack Query 캐시/무효화 ↔ GetX 컨트롤러 + 명시적 재조회.
- **가드 시점**: 렌더 시점(`RequireAuth`) ↔ 라우팅 시점(미들웨어 예정) / 스플래시 분기.
- **QR**: 웹은 `qrcode` data-URL + `<a download>`, 앱은 `qr_flutter` + 시스템 공유 시트.
  웹의 "QR 코드 저장"을 앱에 안 옮긴 건 `share_event_sheet.dart`에 근거가 적혀 있다(갤러리 저장 권한 회피, 링크 복사·포스터로 대체).
- **폼 검증**: RHF + Zod ↔ 컨트롤러 직접 검증(필드 9개라 스키마 라이브러리 미도입).
